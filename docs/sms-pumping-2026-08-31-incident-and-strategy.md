## 배경

- `/api/sms/send-code` 대상 SMS 펌핑 공격. 목적은 인증이 아니라 발송 자체(비용·크레딧 소진). 24시간 발송 1,515건 중 1,474건(97.3%)이 공격이며, 말미에 게이트웨이가 `-201 보유건수 부족`을 반환 — **SMS 잔액 소진 피해 발생.**
- 7월 UA 블랙리스트([route.ts:13-29](../src/app/api/sms/send-code/route.ts#L13-L29))는 4차례 우회당했다: Chrome 150 → stock 안드로이드 크롬 → Whale 모바일 → Firefox 로테이션 → 현재 **Edge 152 정품 UA**. UA 차단은 더 이상 유효하지 않다.
- 정상 고객은 대부분 Google·Naver 광고 유입이므로, 광고 외 유입 일부 차단은 감수한다.

## 분석

공격 1,474건은 아래 세 특징이 **동시에 100% 일치**한다. 로그에 세션 식별자가 없어 개별 분류는 추정이며, 수치는 이 24시간 표본에 한정된다.

1. **IP** — 유니크 1,237개 전부가 하이온넷(HAIONNET-KR) 등록 대역 10개 소속: 49.254.0.0/16, 115.144.0.0/16, 121.126.0.0/16, 124.198.0.0/17, 125.7.128.0/18, 183.78.128.0/19, 203.109.0.0/19, 202.126.112.0/21, 202.133.16.0/20, 202.86.8.0/21 (APNIC RDAP, 2026-08-31 조회). 정상 후보 41건은 통신사(KT·SKT·LG U+) 대역. ※ 운영 결정에 따라 차단 근거가 아닌 **식별 신호로만** 활용.
2. **타이밍** — 간격의 78%가 47~49초, 95%가 ±3초 오차의 48초 배수 격자(48/96/144/192초). 24시간 무휴, 시간당 42~71건 균일. 고정 주기 자동화 작업으로 추정.
3. **referer** — 전부 민짜 `https://www.plankor.kr/report` 고정, 광고 마커(`gclid`·`wbraid`·`n_media`·`NaPm`) 0건. 정상 후보는 `/report/종목코드` 또는 광고 파라미터가 붙는다.

보조 시그니처:

- UA는 Edge 152 **단일 고정** (단, 동일 UA 정상 후보 5건 존재 → UA 단독 판정 불가)
- 전화번호는 중복 없는 난수 생성 패턴 (가운데 블록 첫 자리 2~9 균등, 0·1 부재)
- 공격 집합과 연결되는 verify 호출 0건 — 인증 전환율 0%
- Turnstile은 공격 개시 시 16연속 실패 후 통과 시작 — 솔버 또는 브라우저 자동화로 우회 중

**신뢰 경계**: referer·UA·클라이언트 제출 광고값(sessionStorage/body)은 전부 위조 가능하다. 탐지 신호로만 쓰고, 발송 자격의 단독 증거로 쓰지 않는다.

## 조치 옵션

| | A-1 referer/광고값 검사 | A-2 서버 발급 일회용 광고 세션 | B UA 화이트리스트 |
|---|---|---|---|
| 현재 공격 차단 | 100% (표본 기준) | 100% (직접 호출 차단) | **0%** (Edge 정품 UA) |
| 정상 후보 손실 | 32~54% | 낮음 | 0% 또는 12%+ |
| 우회 비용 | 헤더/바디 1줄 위조 | 랜딩·세션·Turnstile 전체 재현 | UA 1줄 복사 (7월 4회 실증) |

- **B 기각**: 공격 UA가 정품이라 화이트리스트에 들어갈 수밖에 없고, 제외하면 실고객이 차단되며 공격자는 리스트 내 UA로 위장한다(7월 전례 2회). 우회 비용을 높이지 못한다.
- **A-1**: 즉시 적용 가능하나 위조에 약함 → 임시 스토프갭으로만.
- **A-2**: 본 해법. 서버가 광고 랜딩 시 발급·검증하는 일회용 세션만 발송 자격으로 인정.
- **미적용 결정**: 하이온넷 CIDR 차단, 사이트 전체 발송 서킷브레이커는 적용하지 않는다(운영 결정).

## 선택된 전략

**옵션 A를 2단계로 집행한다.** UA는 판정 기준에서 제외하고 기록·분석용 보조 신호로만 유지한다.

**1단계 — 긴급 (즉시)**: referer 완화 필터. 광고 마커 또는 `/report/숫자` referer가 없는 발송 요청을 거부한다. 위조가 시작되면 폐기하는 임시 조치임을 전제한다.

**2단계 — 구조 (본 해법)**: 서버 발급 일회용 광고 세션.

1. 광고 랜딩 감지 시 서버가 세션을 생성하고, 짧은 TTL의 서명된 `HttpOnly`·`Secure`·`SameSite=Lax` 쿠키를 발급한다.
2. 광고 소스·클릭 ID 해시는 서버 측에 저장한다. 클라이언트 제출값만으로 자격을 부여하지 않는다.
3. `send-code`는 유효한 미사용 세션이 없으면 Turnstile·게이트웨이 호출 전에 거부한다.
4. 세션 1개 = 전화번호 1개. 최초 발송과 제한된 재전송 후 소진, 재사용 불가.
5. 세션별 발송량 하드 리밋을 둔다.

**한계**: 서버 세션은 광고 클릭의 진위를 인증하지 못한다(가짜 `gclid` 랜딩 자동화 가능). 목적은 직접 API 호출 차단, 일회용 발송 자격, 비용 한도 부여다.

**차단 응답**: 사유를 특정할 수 없는 일반 오류(403/429)만 반환한다. 우회 힌트 문구 금지 — 7월의 "다른 브라우저로 시도해주세요"가 UA 로테이션을 코치했다. 사일런트 드롭(`ok:true` 후 미발송)은 오탐 사용자 UX 문제와 은폐 효과 한계로 채택하지 않는다.

**모니터링**: 적용 후 verify 성공 급감 = 오탐 신호 → 허용 기준 재검토. 상시 지표: send 대비 verify 비율, 48초 격자 정합도, 하이온넷 대역 점유율, 고유 IP·고유 번호 비율.
