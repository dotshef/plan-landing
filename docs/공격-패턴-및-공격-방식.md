## 공격 방식 상세

### 1. UA 로테이션 타임라인

공격자가 차단에 실시간으로 대응하는 과정이 로그에 그대로 남아 있다.

| 시각 (UTC) | 행동 |
|---|---|
| 07-28 09:47 ~ 13:58 | `Firefox/153.0 (Android Mobile)` UA로 55건 공격 |
| 07-28 15:33 ~ 22:05 | 차단된 `Chrome/150` UA로 재시도 → `ua-blocked` 9건 → **차단 인지** |
| 07-29 05:54 ~ 현재 | `Firefox/153.0 (Windows 데스크톱)` UA로 643건, 속도 2배 증가 |

- 소량이지만 `Firefox/152.0`, `Firefox/150.0`도 섞어 사용 → **버전 로테이션 준비된 봇**.
- Firefox 모바일 시기의 IP 44개 중 **43개가 데스크톱 시기에도 재사용**됨 → 동일 운영자 확정.

### 2. 발송 케이던스 — 기계적 메트로놈

- 요청 간격 중앙값 **90초**. 전체 700개 간격 중 **447개가 60~120초** 구간(60~120초 랜덤 지연을 넣은 봇의 전형).
- **KST 새벽 1~7시 포함 24시간 무휴**로 시간당 25~30건 정속 가동. 해당 심야 시간대 정상 트래픽은 0건.

### 3. 전화번호 — 전량 1회용

- 공격 701건의 수신번호가 **701개 전부 유니크** (재사용 0회). 번호 앞자리(010xx) 분포도 균등 → 구매한 번호 DB를 순차 소진하는 방식.
- 이 때문에 현행 **번호당 레이트리밋(시간당 5회, 30초 쿨다운)은 완전히 무력화**됨 ([verificationStore.ts:25-27](../src/lib/sms/verificationStore.ts#L25-L27)).
- 반면 정상 사용자는 재요청이 존재 (18개 번호 / 21건).

### 4. IP — 국내 레지덴셜 프록시 풀

- 262개 IP를 사용하나 **/24 서브넷 기준 29개**에 불과. 전부 KT 유선 대역에 집중:
  `222.112.161.x`(74건), `222.112.137.x`(68건), `125.133.82.x`(56건), `14.36.28.x`(52건), `211.196.246.x`(40건) 등.
- IP당 최대 8건을 며칠에 걸쳐 분산. 같은 IP의 연속 사용 간격은 중앙값 **218분**, 최소 6.4분 → **per-IP 레이트리밋을 의도적으로 회피**하는 설계.

### 5. verify-code 미호출

- verify-code 호출 16건은 **전부 정상 UA**(삼성 브라우저, 안드로이드 인앱 웹뷰)에서만 발생.
- 공격 트래픽은 발송만 하고 인증 확인을 **한 번도 시도하지 않음** — SMS 펌핑의 전형적 특징이자 UA와 무관한 행동 시그널.

### 6. Turnstile 우회

- 60시간 동안 Turnstile 차단은 **2건뿐**. 공격 트래픽 대부분이 유효한 토큰으로 통과 중 → 토큰 파밍 또는 헤드리스 브라우저 해결로 추정. Turnstile 설정 점검 필요.

## 방어 제안 (효과 순)

1. **단기 — Firefox UA 계열 차단**: 즉시 97% 차단, 현재 오탐 0. 단, 완전일치가 아닌 `Firefox/` **포함 여부**로 검사해야 버전 로테이션에 뚫리지 않음. 곧 우회될 것을 전제로 한 응급조치.
2. **구조적 — /24 서브넷 레이트리밋**: 서브넷당 일일 발송 상한(예: 5건). 공격 서브넷(74건/2일 수준)은 즉시 차단되고, 정상 사용자는 통신사 모바일 대역이라 겹치지 않음. 코드 주석에 이미 계획된 방안.
3. **verify 미수행 자동 블랙리스트**: 발송 후 N분 내 verify 시도가 없는 IP/서브넷에 누적 점수를 매겨 차단. 공격자의 행동 자체가 시그널이므로 UA 변경으로 우회 불가.
4. **Turnstile 강화**: managed/interactive 모드 전환, 토큰 1회용(재사용 불가) 검증 여부 점검.
5. **야간 강화 모드**: KST 01~07시는 현재 100% 공격 트래픽 → 해당 시간대만 임계치 대폭 하향.
