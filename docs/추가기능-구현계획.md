# 추가기능 구현 계획

`docs/추가기능설계.md`(요구사항)와 `docs/prototype.html`(시안)을 현재 코드베이스에 맞춰 구현 가능한 형태로 옮긴 문서다.
시안은 참고용이며 레이아웃은 기존 사이트 톤(인라인 스타일 + `responsive-*` 유틸)에 맞춰 새로 구성한다.

## 0. 확정된 결정사항

구현 착수 전 협의로 확정된 항목. 요구사항 문서와 다른 부분은 **이 문서가 우선**한다.

| 항목 | 결정 | 요구사항 문서와의 차이 |
|---|---|---|
| 관리자 인증 | 자체 세션(scrypt 해시 + httpOnly 쿠키). 인가 판정은 앱 서버 한 곳(`requireAdmin`)에서만 | — |
| 영업이익 증가율 | **직전 분기 대비(QoQ)**. N분기 vs N-1분기 | 시안은 YoY 표기 → QoQ로 정정 |
| 업종 PER | **TTM 분기 PER 자동 계산** — 종목별 `분기말 종가 ÷ TTM EPS`의 단순 산술평균 | 초기안(fundamental.per 스냅샷)에서 변경. KRX·네이버 공표 코스피 PER(TTM)과 축이 맞아 "코스피 평균 이하" 비교가 성립 |
| PER 결측·적자 종목 | TTM EPS ≤ 0이거나 EPS 누락으로 계산 불가한 종목은 평균에서 **제외**, 관리자 화면에 제외 안내만 표시(반영 차단 아님) | 요구사항에 규정 없음 |
| 외국인 순매수 | `investor_trend_daily.foreign_net_amount`(금액)를 섹터 내 **합산** | 요구사항은 `foreign_net`(수량) 지정 + "단순 산술 평균" → 금액·합산으로 정정 |
| 분기 재무값 처리 | KIS 분기 손익계산서·재무비율은 **YTD 누적** — 단독 분기값은 차분으로 파생(1분기는 그대로). 삼성전자 실측으로 확인 | 요구사항에 규정 없음 |
| 신청 폼 | 기존 `report_request` 재사용. SMS 인증·Turnstile·중복방지·메일 알림 그대로 유지. **출처 구분 컬럼만 추가** | — |
| 반영 버튼 | Vercel 재배포가 아니라 **계산 → 스냅샷 저장 → 공개 전환**. 버튼 문구는 "**방문 사이트 반영**" | "사이트 배포 버튼" 명칭 변경 |
| 섹터 페이지 부가 요소 | **주도종목 잠금 카드 유지**, **분기 영업이익 추이 차트 유지**. 섹터 부제문·체크포인트·직전 발간 대비 변경 표시는 **범위 제외** | 시안에만 있던 요소 정리 |

## 3. DB 마이그레이션

기존 번호를 이어 `0011`부터. 모든 신규 테이블은 **RLS 미사용**, 서버 service_role 전용.

### 0011_admin_auth.sql

```sql
create table if not exists admin_user (
  id                        bigserial primary key,
  email                     text not null unique,
  name                      text,
  password_hash             text not null,              -- scrypt: N$r$p$salt$hash (평문·가역 저장 금지)
  must_change_password      boolean not null default true,
  temp_password_expires_at  timestamp,                  -- 임시 비밀번호 만료(발급 + 7일)
  fail_count                smallint not null default 0,
  locked_until              timestamp,                  -- 5회 실패 시 10분 잠금
  invited_by                bigint references admin_user(id),
  last_login_at             timestamp,
  deleted_at                timestamp,                  -- soft delete (감사 목적)
  created_at                timestamp not null default (now() at time zone 'Asia/Seoul')
);

create table if not exists admin_session (
  token_hash text        primary key,                   -- 랜덤 32B의 sha256. 원문은 쿠키에만 존재
  admin_id   bigint      not null references admin_user(id) on delete cascade,
  expires_at timestamptz not null,                      -- 순수 만료 판정용이라 timestamptz
  created_at timestamp   not null default (now() at time zone 'Asia/Seoul')
);
create index if not exists admin_session_admin_idx on admin_session (admin_id);
```

### 0012_trial_asset.sql

```sql
create table if not exists trial_asset (
  id           bigserial primary key,
  kind         text not null check (kind in ('sms', 'chart', 'review')),
  group_no     smallint,                                -- sms·chart를 한 세트로 묶는 번호. review는 null
  storage_path text not null,                           -- Storage 오브젝트 경로
  alt          text,
  sort_order   int  not null default 0,
  created_at   timestamp not null default (now() at time zone 'Asia/Seoul')
);
create index if not exists trial_asset_kind_sort_idx on trial_asset (kind, sort_order);
```

- `review`는 최대 3개 — DB 제약이 아니라 업로드 API에서 count 검사 후 거부한다(제약 위반 에러보다 명확한 메시지를 주기 위함).
- `sms`/`chart`는 `group_no`가 같은 것끼리 좌우로 짝지어 렌더한다. 세트는 여러 개 등록 가능.

### 0013_sector_report.sql

```sql
create table if not exists sector_report (
  id             bigserial primary key,
  year           int      not null,
  quarter        smallint not null check (quarter between 1 and 4),
  kospi_avg_per  numeric,                                -- 관리자 수동 입력
  status         text     not null default 'draft' check (status in ('draft', 'published')),
  base_date      date,                                   -- 계산 기준일(반영 시각의 KST 날짜)
  computed_at    timestamp,
  published_at   timestamp,
  created_at     timestamp not null default (now() at time zone 'Asia/Seoul'),
  unique (year, quarter)
);

create table if not exists sector (
  id         bigserial primary key,
  report_id  bigint not null references sector_report(id) on delete cascade,
  name       text   not null,                            -- 섹터 이름
  theme      text   not null,                            -- 섹터 주제
  sort_order int    not null default 0,
  -- 반영 시점에 확정되는 계산 스냅샷 (draft 상태에서는 전부 null)
  op_growth_rate            numeric,                     -- 영업이익 증가율 %
  sector_per                numeric,                     -- 업종 PER
  trading_value_growth_rate numeric,                     -- 거래대금 증가율 %
  foreign_net_amount        bigint,                      -- 외국인 순매수 금액(원)
  op_trend                  jsonb,                       -- [{ "label": "3Q26", "value": 12345 }] 차트용
  unique (report_id, name)
);

create table if not exists sector_stock (
  sector_id  bigint not null references sector(id) on delete cascade,
  code       text   not null references stock(code),
  sort_order int    not null default 0,
  primary key (sector_id, code)
);
```

- 퍼블릭 `/sector`는 `status='published'` 중 `published_at` 최신 1건만 렌더한다.
- 반영은 같은 보고서 행을 `draft → published`로 전환한다. 이후 수정은 published 상태에서 편집하고 다시 반영한다 — 스냅샷은 반영 시점에만 갱신되므로 편집 중에도 퍼블릭 표시값은 흔들리지 않는다.

### 0014_report_request_source.sql

```sql
alter table report_request
  add column if not exists source_page text not null default 'main',
  add column if not exists requested_items text;         -- '영상 속 자료 받기'에서 선택한 자료명(쉼표 구분)

alter table report_request
  drop constraint if exists report_request_source_page_check;

alter table report_request
  add constraint report_request_source_page_check
  check (source_page in ('main', 'trial', 'indicators', 'sector'));
```

### 0015_financial_ratio_quarterly.sql

```sql
-- 분기 재무비율 수집을 위한 연간/분기 구분 (income_statement와 동일 패턴)
alter table financial_ratio add column if not exists period_type char(1) not null default 'A';
alter table financial_ratio drop constraint financial_ratio_pkey;
alter table financial_ratio add primary key (code, period_type, period);
```

- 야간 cron의 `ratio` 데이터셋을 연간(DIV=0)에 더해 **분기(DIV=1)도 수집**하도록 확장한다. 분기 조회는 호출 1회에 최근 30개 분기를 반환한다.
- **주의**: KIS 분기 재무(손익계산서·재무비율)는 YTD 누적값이다. DB에는 받은 그대로(누적) 저장하고, 단독 분기값·TTM은 계산 시점에 차분으로 파생한다.
- 겸사겸사 `ratio` 데이터셋의 API 경로가 `/finance/balance-sheet`로 잘못 적혀 있는 것(`src/lib/kis/datasets/stock.ts` — TR id `FHKST66430300`으로 라우팅돼 동작은 함)을 `/finance/financial-ratio`로 바로잡는다.

## 4. 관리자 인증

### 4.1 원칙

- 인가 판정은 `src/lib/admin/session.ts`의 `requireAdmin()` 단 한 곳에서만 한다. 서버 컴포넌트·API 라우트 모두 이 함수를 통과해야 한다.
- `middleware.ts`는 쿠키 유무만 보고 `/admin/login`으로 리다이렉트하는 **UX 보조**이며, 실제 검증은 하지 않는다(엣지에 중복 판정 지점을 만들지 않기 위함).
- RLS는 사용하지 않는다. DB는 기존과 동일하게 service_role 단일 커넥션이다.

### 4.2 비밀번호·세션

- 해시: `node:crypto`의 `scrypt`(N=16384, r=8, p=1, salt 16B). 신규 의존성 없음.
- 검증: `timingSafeEqual`.
- 세션 토큰: `randomBytes(32).toString('base64url')`. DB에는 sha256 해시만 저장.
- 쿠키: `admin_session`, `httpOnly`, `secure`, `sameSite=lax`, `path=/`, 만료 12시간.
- 로그인 실패 5회 → `locked_until` 10분. 성공 시 `fail_count` 리셋.
- 비밀번호 변경·계정 삭제·임시 비번 재발급 시 해당 사용자의 `admin_session`을 **전부 삭제**한다.

### 4.3 초대 흐름

1. `/admin/users`에서 이메일 입력 → `POST /api/admin/users/invite`
2. 서버가 임시 비밀번호(12자, 혼동 문자 제외한 영숫자)를 생성해 해시 저장, `must_change_password=true`, `temp_password_expires_at = now + 7일`
3. Resend로 초대 메일 발송 — 본문에 로그인 링크(`https://www.plankor.kr/admin/login`)와 임시 비밀번호 평문. 평문은 이 메일에만 존재하며 DB·로그에 남기지 않는다.
4. 수신자가 링크 → 로그인 → `must_change_password`면 `/admin/password`로 강제 이동. 이 상태에서는 다른 `/admin/*` 접근이 전부 `/admin/password`로 리다이렉트된다.
5. 새 비밀번호 설정 시 `must_change_password=false`, `temp_password_expires_at=null`
6. 재발급: `POST /api/admin/users/[id]/reset-password` — 2~3 반복 + 기존 세션 폐기

**필요한 코드 변경**: `sendMail()`에 `to?: string` 파라미터 추가(미지정 시 기존처럼 `EMAIL_TO`). 발신 도메인 `plankor.kr`은 이미 Resend 인증돼 있다.

### 4.4 최초 관리자 생성

마이그레이션에 계정을 심지 않는다. `scripts/create-admin.ts`(tsx 실행)로 1회 생성한다 — 이메일·비밀번호를 인자로 받아 해시 후 insert하고 `must_change_password=false`로 둔다.

## 5. 4분기 섹터 파이프라인

### 5.1 분기 정의

- 재무 기간키: `period = ${year}${String(quarter * 3).padStart(2, '0')}` (`income_statement.period_type='Q'`)
- N-1분기: `quarter - 1`, 1분기면 전년 4분기
- 시세 구간: Q1 `01-01~03-31`, Q2 `04-01~06-30`, Q3 `07-01~09-30`, Q4 `10-01~12-31`
- 분기 라벨 변환은 기존 `src/data/loader.ts`의 `quarterLabel()` 규칙(03→1Q…12→4Q)을 공용 모듈로 추출해 재사용한다.

> **확인됨**: KIS 분기 손익계산서·재무비율(`FID_DIV_CLS_CODE=1`)은 **YTD 누적값**이다(삼성전자 실측 — 202512 누적이 연간 리포트와 일치). 단독 분기값 = `누적(N) − 누적(N-1)`, 1분기는 누적 그대로. 매출·영업이익·순이익·EPS 같은 흐름 항목만 차분하고, BPS 등 잔액 항목은 그대로 쓴다.
> **전제**: 12월 결산 법인 기준. 결산월이 3·6·9·12월이 아닌 종목은 기간키가 맞지 않아 "영업이익이 제공되지 않았습니다"로 잡힌다.

### 5.2 계산식

모두 **종목 단위로 먼저 구한 뒤 섹터에서 집계**한다.

| 지표 | 종목 값 | 섹터 집계 |
|---|---|---|
| 영업이익 증가율 | `(OP_N - OP_{N-1}) / abs(OP_{N-1}) × 100` — OP는 누적 차분한 단독 분기값 | 단순 산술평균 |
| 업종 PER (TTM) | `N분기 마지막 거래일 종가 ÷ TTM EPS`. TTM EPS = `누적EPS(N) + 연간EPS(전년) − 누적EPS(전년 동분기)` — `financial_ratio`(분기·연간) + `price_daily` | TTM EPS > 0인 종목만 단순 산술평균 |
| 거래대금 증가율 | `(Σ trading_value(N) - Σ trading_value(N-1)) / Σ trading_value(N-1) × 100` | 단순 산술평균 |
| 외국인 순매수 | `Σ foreign_net_amount(N)` | **합산** |
| 영업이익 추이(차트) | 최근 4개 분기 단독 영업이익(누적 차분) | 종목 합산값의 분기별 시계열 → `op_trend` |

업종 PER은 TTM 기준이므로 KRX·네이버가 공표하는 코스피 평균 PER(TTM)과 직접 비교할 수 있고, "N분기말 기준 업종 PER" 표기가 정확해진다. 증권사 MTS의 분기 PER(분기말 종가 ÷ 단독 분기 EPS — 삼성전자 실측으로 공식 검증)은 연간 축 대비 약 4배 부풀려지는 값이라 채택하지 않는다. **관리자가 입력하는 코스피 평균 PER도 TTM 기준 공표값을 쓴다.**

### 5.3 검증 규칙 (`GET /api/admin/sector/validate`)

섹터에 등록된 모든 종목에 대해 아래를 검사한다.

| 검사 | 조건 | 표시 | 반영 차단 |
|---|---|---|---|
| N분기 영업이익 | `income_statement(Q, N)` 행 없음 또는 `operating_profit` null | 빨강 `N분기 영업이익이 제공되지 않았습니다.` | 차단 |
| N-1분기 영업이익 | 위와 동일(N-1) | 빨강 `N-1분기 영업이익이 제공되지 않았습니다.` | 차단 |
| 분모 0 | `OP_{N-1} = 0` | 빨강 `N-1분기 영업이익이 0이라 증가율을 계산할 수 없습니다.` | 차단 |
| 거래대금 완전성 | 분기 거래일 집합에 없는 날짜가 해당 종목 `price_daily`에 있음 | 빨강 `N분기 거래대금 데이터가 불완전합니다` | 차단 |
| 외국인 순매수 완전성 | 위와 동일, `investor_trend_daily` 기준 | 빨강 `N분기 외국인 순매수 데이터가 불완전합니다` | 차단 |
| PER 결측·적자 | TTM EPS 계산에 필요한 분기·연간 EPS가 없거나 TTM EPS `<= 0` | 노랑 `업종 PER 평균에서 제외됩니다` | 차단 안 함 |

**거래일 집합 산출**: KRX 영업일 달력이 DB에 없으므로, 해당 분기 구간의 `price_daily`에 존재하는 **전 종목 DISTINCT date**를 그 분기의 거래일로 간주한다. 종목별 날짜 집합이 이 집합을 모두 포함해야 완전한 것으로 본다.

반영 차단은 **UI 비활성화 + 서버 재검증 이중**으로 건다. `POST /api/admin/sector/publish`는 요청을 받으면 검증을 다시 수행하고, 실패 시 409와 위반 목록을 반환한다(요구사항의 "계산이 불가하도록 서버에서 처리").

### 5.4 과거 분기 데이터 백필 — 온디맨드

야간 cron은 `price_daily` 최근 40일, `investor_trend_daily` 최근 약 30영업일만 수집하므로 cron 가동 이전 분기는 비어 있다. 이를 **섹터에 등록된 종목에 한해 온디맨드 백필**로 채운다 (`POST /api/admin/sector/backfill`).

- `investor-trade-by-stock-daily`(FHPTJ04160001, custtype P)는 기준일부터 과거 30영업일의 **수급(수량·금액)과 시세(OHLCV·거래대금)를 한 번에** 반환한다 — 실측 확인. 기준일을 뒤로 밀며 반복 호출하면 `price_daily`와 `investor_trend_daily`를 **동시에** 채울 수 있어 시세 API를 따로 부를 필요가 없다. 2개 분기 ≈ 120영업일 → 종목당 4~5회.
- `finance/financial-ratio`·`finance/income-statement`(DIV=1)는 호출 1회에 최근 30개 분기를 반환 → 종목당 각 1회.
- 합계 종목당 6~7회. 30종목 기준 약 200회 — 12req/s 큐에서 약 20초.
- 모든 적재는 기존 PK 기준 upsert라 **멱등** — 몇 번을 다시 돌려도 결과가 같다.
- 흐름: 관리자가 섹터에 종목 등록 → 백필 실행 → 완료 후 validate 재실행 → 경고 해소 확인.
- 관리자 섹터 화면 상단에 **보유 데이터 시작일**(각 테이블의 `min(date)`)을 표시한다.

### 5.5 반영(publish) 절차

```
POST /api/admin/sector/publish
  1) requireAdmin()
  2) 서버 재검증 → 위반 있으면 409 { violations: [...] }
  3) 섹터별 지표 4종 + op_trend 계산
  4) sector 행에 스냅샷 UPDATE
  5) sector_report: status='published', base_date=오늘(KST), computed_at·published_at 갱신
  6) 200 { ok: true }
```

퍼블릭 `/sector`는 `force-dynamic`이라 다음 요청부터 즉시 새 값이 보인다. Vercel 재배포는 하지 않는다.

### 5.6 퍼블릭 `/sector` 렌더

- 상단: `YYYY년 N분기`, 기준일, 선정 기준 문구(정적)
- 섹터 비교 표: 섹터별 지표 4종 + `kospi_avg_per`
- 섹터별 블록: 영업이익 추이 막대 차트(`op_trend`, 데이터 없는 분기는 빈 칸), 지표 4개 카드, 코스피 평균 PER 대비 막대, **최근 뉴스 최대 5건**, **주도종목 잠금 카드**
- 뉴스: 렌더 시점에 `news`에서 `code in (섹터 종목들)` → `published_at desc limit 5` 실시간 조회(스냅샷 아님)
- 하단: 신청 폼(`source_page='sector'`)

## 6. 이미지 스토리지 (추천주 7일 체험)

- Supabase Storage 버킷 `public-assets` (public read). 경로: `trial/{kind}/{uuid}.{ext}`
- 업로드는 **서버 라우트에서 service_role로만** 수행한다. 클라이언트에서 Storage로 직접 올리지 않는다(브라우저에 노출할 anon key를 이 프로젝트는 쓰지 않는다).
- 제한: `image/jpeg|png|webp`, 5MB. 위반 시 400.
- 삭제는 Storage 오브젝트 삭제 + `trial_asset` 행 삭제를 함께 수행한다. Storage 삭제가 실패해도 행은 지워 화면에서 사라지게 한다(고아 오브젝트는 허용).
- 렌더는 공개 URL을 `<img>`로 직접 사용한다. `next/image`를 쓰려면 `next.config.ts`에 Supabase 호스트 `remotePatterns` 추가가 필요하므로, v1은 `<img>` + 명시적 `width/height`로 간다.
- 관리자 화면(`/admin/trial`): 세트(`group_no`)별 문자캡처/차트 업로드, 후기 3칸(초과 시 업로드 버튼 비활성 + 서버 400).

## 7. 퍼블릭 페이지 구성

### 7.1 메인 — '지금 바로 받아보실 수 있는 혜택'

`ReportCardsSection` 아래에 카드 3개 섹션을 추가한다. 각 카드는 `/trial`, `/indicators`, `/sector`로 이동. 기존 섹션과 같은 `responsive-section-shell` 래퍼·카드 스타일을 쓴다.

### 7.2 `/trial` — 추천주 7일 체험

정적 영역(히어로, 선정 4단계, 7일 일정 표, CTA 폼) + 동적 영역(문자캡처·차트 세트, 후기 이미지 최대 3).
이미지가 하나도 없으면 해당 섹션 전체를 숨긴다 — 빈 점선 자리표시자를 실서비스에 노출하지 않는다.

### 7.3 `/indicators` — 영상 속 자료 받기

전부 정적. 자료 선택 칩(증시 캘린더·엑스레이 지표 등)은 코드 상수 배열로 두고, 선택값은 폼 제출 시 `requested_items`로 전송한다. 하단 발송 기록 이미지는 요구사항대로 **정적 이미지 + 코드 임베드**(`public/images/...`)이며 관리자 관리 대상이 아니다.

### 7.4 신청 폼 공통

기존 `useReportRequest` 훅과 `POST /api/report-request`를 그대로 쓴다. 추가되는 것:

- 훅 인자에 `sourcePage`, `requestedItems` 추가
- API에서 두 값을 검증 후 `report_request`에 저장(허용값 밖이면 `'main'`으로 정규화)
- 알림 메일 템플릿(`buildReportRequestEmailTemplate`)에 "유입 페이지"·"요청 자료" 행 추가

SMS 인증·Turnstile·2개월 중복 접수 차단은 4개 페이지 모두 동일하게 적용된다.

## 10. 착수 전 확인이 필요한 항목

1. **`/indicators` 하단 정적 이미지 원본** — 시안에는 base64로 24장이 들어 있다. 실제 사용할 파일을 `public/images/`에 받아야 한다.
2. **`/indicators`, `/sector` 최종 경로명** — 이 문서는 `/indicators`, `/sector`로 가정했다.
3. **최초 관리자 계정 이메일** — `scripts/create-admin.ts` 실행 시 사용할 주소.
4. **(별개 버그) 기존 종목 페이지 분기 실적 차분 누락** — `src/data/loader.ts`의 `QUARTERLY_EARNINGS`가 KIS 누적값을 차분 없이 분기 실적으로 표시 중. 현재 사이트의 분기 매출·영업이익·영업이익률이 실제와 다르다. 이번 작업과 별개로 수정 필요.

> 이전 확인 항목이었던 "분기 데이터 보유 범위"와 "분기 영업이익 누적 여부"는 실측으로 해소됐다 — 각각 §5.4(온디맨드 백필), §5.1(YTD 누적 확인) 참조.
